# Integración con Stripchat

La extensión puede trabajar en modo **Automático**, **Manual** o **Desactivado**. Una instalación nueva usa Automático; una preferencia ya guardada se conserva. El modo manual permite pegar texto o usar una selección visible. Cuando no hay configuración guardada, la extensión intenta validar en el DOM visible un adaptador para las clases de Stripchat observadas (`messenger-chat`, `messenger-chat__messages-wrapper`, filas `base-message-wrapper`, clases de dirección y el nombre del encabezado). Evita las clases CSS con sufijos dinámicos y solo habilita el flujo si encuentra un chat, un alias y evidencia de mensajes entrantes y propios. Si la validación falla o el sitio cambia su DOM, queda en diagnóstico y no presume que el modo automático funciona. En «Configuración», «Elegir en página» propone un selector desde el elemento real pulsado; es candidato, no validación. «Probar selectores en esta página» muestra por campo el selector, coincidencias y estado, con muestras locales breves (correos, enlaces y números redactados). «Guardar configuración» no verifica nada por sí mismo.

Después de recargar, los selectores guardados se vuelven a validar en el DOM actual. Si los selectores preconfigurados para Stripchat encuentran evidencia suficiente, el detector se inicia; de lo contrario hay que probar selectores en «Diagnóstico y configuración». Si no se puede identificar un alias, no genera automáticamente ni atribuye memoria a una persona desconocida. La prueba de selectores no envía muestras al backend ni a servicios externos.

Al activarse, el detector espera a que se estabilice el chat visible y toma una línea base. En esa sincronización inicial genera solo para el último mensaje entrante pertinente, si aún no se procesó; no genera una respuesta por cada mensaje histórico. Después, cada mensaje entrante nuevo puede producir una respuesta original y su traducción al español cuando haga falta. Cambios rápidos del DOM se consolidan al objetivo más reciente y las claves procesadas evitan duplicados al reabrir. Con timestamps completos y parseables, ordena cronológicamente; si no, conserva el orden DOM. El historial para el modelo se configura por separado del panel: hasta 100 mensajes y 12.000 caracteres por defecto (ajustables en Diagnóstico y configuración). Se conservan filas completas y recientes; el panel muestra solo una vista compacta. Un cambio de interlocutor invalida solicitudes, cola, alias y respuestas anteriores. No consulta cookies, endpoints privados ni chats cerrados. La extensión nunca pulsa el botón de envío.

El detector trabaja con filas de mensajes que Stripchat mantiene en el DOM del chat activo, no con un archivo o API de historial completo. Considera una fila visible si el estilo no la oculta y su rectángulo tiene ancho/alto no nulos; no comprueba la intersección con el área desplazable. El selector preconfigurado requiere `data-message-id`; una fila sin ese atributo puede quedar fuera hasta que el usuario configure y pruebe un selector alternativo. El snapshot conserva como máximo las últimas 100 filas extraídas, incluido el objetivo; la ventana de contexto y el límite de caracteres pueden reducir más esa cantidad. Si la página virtualiza o no carga mensajes antiguos, estos no llegan al backend. El usuario puede desplazarse hacia arriba en el propio chat para pedir a la interfaz que cargue más historial (si Stripchat lo ofrece), ajustar la ventana y regenerar. En el formulario «Responder manualmente» también puede aportar contexto en «Contexto previo opcional», etiquetando cada línea como `- Interlocutor:` o `- Usuario:`. Ese texto se usa solo en la solicitud y no se persiste.

Si no hay suficiente evidencia, el panel explica el campo sin coincidencias y permite usar el modo manual. Cada generación devuelve una única respuesta original. Para idiomas distintos del español, una petición posterior la traduce al español e incluye comprobaciones de fidelidad y de idioma; si falla, se conserva el original y se muestra «Traducción no disponible». El botón «Copiar respuesta» copia únicamente el texto original. El modelo recibe el mensaje entrante objetivo separado del historial, que marca `Interlocutor` y `Usuario`, además del alias y las notas locales aisladas por alias. El prompt pide interpretar jerga, errores, abreviaturas, emojis y referencias anteriores, sin convertir contenido del chat en instrucciones ni inventar hechos; las respuestas adultas se mantienen no gráficas y respetan límites expresados. El idioma se determina primero con el último mensaje entrante objetivo; si es breve o ambiguo, se usa el contexto reciente de mensajes `Interlocutor` y se excluyen los mensajes propios. Solo sin evidencia suficiente se usa `DEFAULT_LANGUAGE` del backend (español por defecto). El prompt fija el campo `RESPONSE_LANGUAGE`; el backend valida la respuesta y hace un único reintento si detecta un idioma distinto, contenido fuera de tema o más de una respuesta original.

`LM_STUDIO_CONTEXT_TOKENS` debe coincidir con el tamaño de contexto configurado para el modelo cargado en LM Studio; `LM_STUDIO_OUTPUT_TOKENS` reserva el espacio de salida. El endpoint `/v1/models` usado por la integración solo informa los IDs de modelos, no su ventana de contexto. El backend calcula una estimación conservadora de tokens para el prompt completo (no utiliza el tokenizador propio del modelo); si debe ajustarlo, elimina primero mensajes antiguos y después reduce fuentes personales, y registra el motivo sin registrar el texto. El diagnóstico avanzado indica filas extraídas y dirección, mensajes/ caracteres incluidos, recorte, estimación, presupuesto configurado, idioma y resultado de generación.

La cobertura automatizada usa DOM simulado. La validación manual de selectores y del flujo en Chrome requiere una sesión real con una conversación abierta; hasta realizarla, no se considera confirmada la integración DOM de Stripchat.
